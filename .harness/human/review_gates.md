# Human-in-the-Loop 게이트 정의

> 이 게이트들은 AI가 **반드시 사람에게 확인을 받아야 하는 시점**을 정의합니다.
> 게이트를 건너뛰면 데이터 손실, 서비스 장애, 비용 낭비가 발생할 수 있습니다.

---

## Gate #1 — 팟캐스트 재생성

**트리거**: NotebookLM에 새 팟캐스트 생성을 요청하기 전

**왜 필요한가**:
- NLM 팟캐스트 생성은 크레딧 소모 + 수 분 소요
- 기존 파일이 덮어쓰여지면 복구 불가
- 잘못된 내용으로 생성되면 재작업 필요

**AI가 해야 할 일**:
```
1. 현재 R2에 있는 파일 버전 확인
2. 재생성이 필요한 이유 사용자에게 설명
3. 어떤 챕터의 몇 번 에피소드를 생성할지 명시
4. "진행할까요?" → 사용자 "예" 확인 후 진행
```

**승인 후 실행**:
```python
python .harness/skills/podcast_manager.py --chapter ch0N --action restore
```

---

## Gate #2 — 프로덕션 배포

**트리거**: `vercel deploy` 또는 `git push origin main` 실행 전

**왜 필요한가**:
- 배포는 즉시 수천 명 사용자에게 영향
- 잘못된 배포는 서비스 중단 초래
- 롤백은 가능하지만 시간 소요

**AI가 해야 할 일**:
```
1. npm run test 결과 사용자에게 공유
2. 변경된 파일 목록 명시 (git diff --stat)
3. "배포할까요?" → 사용자 확인 후 진행
```

**자동 배포 허용 조건** (승인 없이 가능):
- 사용자가 명시적으로 "배포해줘" 라고 했을 때
- 테스트 통과 확인됨
- 변경이 단순 버그픽스 수준

---

## Gate #3 — 콘텐츠 삭제 / 대규모 변경

**트리거**: 다음 작업 전
- 챕터 본문 텍스트 삭제 또는 대폭 축소
- 팟캐스트 오디오 플레이어 제거
- 이미지 또는 강의 자료 링크 제거
- 한 번에 3개 이상 파일 대규모 수정

**AI가 해야 할 일**:
```
1. 삭제/변경 대상 항목 정확히 나열
2. 변경 이유 설명
3. 영향 범위 설명 (어떤 사용자에게 무슨 영향)
4. 복구 방법 (git revert) 설명
5. 사용자 승인 후 진행
```

---

## Gate #4 — 환경변수 / 인증 변경

**트리거**: `.env` 파일 수정 전

**왜 필요한가**:
- 잘못된 키 → Supabase 인증 실패 → 전체 서비스 로그인 불가
- R2 키 변경 → 미디어 파일 접근 불가

**AI가 해야 할 일**:
```
1. 변경할 키와 이유 명시
2. 영향 범위 설명
3. 사용자 직접 수정 요청 (AI가 .env를 직접 보여주지 않음)
```

---

## Gate #5 — 예상치 못한 에러

**트리거**: 다음 상황에서

- 스크립트가 2회 이상 연속 실패
- 예상치 못한 파일이 삭제됨
- 데이터베이스 에러 발생
- 배포 후 URL 접근 불가

**AI가 즉시 해야 할 일**:
```
1. 작업 즉시 중단
2. 에러 내용 전체 사용자에게 보고
3. 현재까지 변경된 파일 목록 공개
4. 복구 옵션 제시 (git revert / 수동 복구)
5. 사용자 지시 기다림
```

## 게이트 판단 빠른 참조표

| 작업 | 게이트 | 자동화 허용? |
|------|--------|------------|
| 팟캐스트 재생성 요청 | #1 | 항상 사람 확인 |
| HTML 소규모 수정 | 없음 | 자동 |
| 배포 (명시적 요청) | #2 | 사용자 "배포해줘" 시 자동 |
| 본문 삭제 | #3 | 항상 사람 확인 |
| .env 수정 | #4 | 항상 사람 직접 |
| 연속 에러 | #5 | 즉시 중단·보고 |
| 검증 스크립트 실행 | 없음 | 자동 |
| R2 업로드 | 없음 (재생성 아닐 때) | 자동 |
